# 轻量记忆模式

默认 `MEMORY_MODE=lite`。长期记忆仍须 `MEMORY_ENABLED=true`，并服从用户记忆开关。
Host 内执行，无新增进程、数据库或向量模型依赖。原有文档 RAG 不变。

当前自动提取版已于 2026-11-10 部署到 215，五进程健康。服务器最终回归 259 项通过；历史 14 个记忆相关失败案例复测 8 项通过，详见 [部署与正式复测报告](MEMORY_AUTO_RETEST_20261110.md)。文末保留此前显式记忆版本的部署记录。

## 行为

- 每个新输入落库后、上下文装配前，进行一次限时结构化提取。自动范围为用户直接表达的稳定长期偏好；无需出现“记住”。明确的记住、记一下、记着、修改、忘记继续支持。
- 临时要求、引文、假设、第三人信息及模型推测不自动保存。项目事实继续通过显式入口；自动提取保留完整业务原文，只有成功的纯显式记忆操作才提前结束。
- 模型仅提供操作提案；SQLite 事务校验来源、身份、范围、版本和输入先后顺序。
- 保存用户原文摘录，避免把模型改写的相反含义当成事实。
- 变更与回执同一事务提交。成功、NOOP、失败、关闭均按 input_id 保存处理结果；重复输入返回原回执，研究任务失败不会撤销已提交记忆。已删除偏好不自动复活；用户可以显式重新保存。
- 提取超时、无效提案、并发冲突或容量不足记录未保存并继续业务，不增加后台重试队列。取消和数据库故障仍向上传递，不能冒充已持久化。已记录的失败输入恢复时不会重复抽取，可在后续新输入重试。
- Host 统一附加提交回执。无成功回执时，提示词和输出守卫约束保存承诺；守卫覆盖常见中英文虚假保存语句，在流式事件及最终答案落库前执行，不作为任意自然语言语义正确性的证明。
- 纯记忆请求绕过业务 Planner/Worker/Critic；混合请求携带回执继续执行。
- 跨会话直接读取当前用户全局与当前项目的有效记忆。默认最多 40 条、6000 字符；
  超限明确报错，不假装没有记忆。可用现有记忆面板清理。新增超限时事务回滚。
- 抽取上下文只附带预算内的有效记录和最多 20 条近期墓碑；提交时按用户、范围、事实键及原内容查完整数据库。历史删除记录不占有效容量，不会因累计删除超过 200 条而永久拒绝新记忆。
- 保留最近 6 轮原话，超过历史软预算一半时尝试生成一份滚动摘录摘要。
  摘要只保留原文片段，失败时旧摘要及未覆盖原话保持不变；原始输入不删除。
- 不自动解释复杂日程事件。摘要与解析仍可能遗漏或误选原文，需真实模型场景评测。

## 配置

```dotenv
MEMORY_MODE=lite
MEMORY_ENABLED=true
MEMORY_LITE_LIMIT=40
MEMORY_RECENT_TURNS=6
MEMORY_LITE_TIMEOUT_S=30
RECOVERY_MAX_RETRIES=3
RECOVERY_RETRY_DELAY_S=3
```

每轮一般增加一次提取模型调用；结构化输出不合法时，沿用共享模型接口的有限纠错重试，整个提取仍受 `MEMORY_LITE_TIMEOUT_S` 限制。

## 持久化与恢复

| 数据 | 复用的持久记录 |
|---|---|
| 会话与原始输入/回答 | conversations、turns、turn_inputs |
| 用户偏好及来源、版本、删除标记 | memories、memory_versions、explicit_memory_sources |
| 每条输入的记忆处理结果 | explicit_memory_receipts（沿用旧表名） |
| 计划、子任务状态、已完成结果及请求信息 | runs.context 中的 orchestrator checkpoint |
| 浏览器断线期间的进度与答复 | events 及事件游标 |

启动恢复使用原 run_id。已完成子任务不重新执行；远端任务先查询再发送，工具结果复用持久回执。连接异常默认最多自动恢复 3 次，仍不可用时进入 paused；“继续”清除连接重试计数并重新分配运行时间预算。业务错误不按断网无限重试。

恢复沿用已保存的上下文及请求参数。新增无关偏好供后续运行使用，不打断旧任务；已经注入的记忆发生修改、删除、范围变化或被禁用时阻止旧上下文继续使用。

续答粒度为计划/子任务，未完成的模型生成可以重试，不恢复模型内部 token 状态。未知结果的写工具不自动重复执行。数据库需保留在持久磁盘上；当前方案使用 SQLite，并未部署 PostgreSQL。

旧的 memory_jobs/context_jobs 保留但轻量模式不消费、不新增；新建的
explicit_memory_receipts / explicit_memory_sources / lite_summaries 不修改旧表数据。
长期事实仍使用 memories 表和现有删除墓碑、版本、用户开关。
`MEMORY_MODE=legacy` 可恢复旧逻辑，但旧队列会重新参与处理，切换前须备份并审查待处理任务。
旧模式原有缺陷不属于轻量模式修复范围。
